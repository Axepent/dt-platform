# Відповідність платформи еталонній моделі ISO 23247

## Склад об’єкта за категоріями OME

| Категорія OME | Відповідність у проєкті | Межі моделювання |
|---|---|---|
| Обладнання | Манекен, шарнірні вузли, приводи, контролер, датчики кутів, струму, температури й напруги, кінцевий вимикач та аварійна кнопка. | Моделюються шість кутових координат S-01…S-06, параметри S-07…S-09 та дискретні стани S-10 і S-11. Струм, температура й кінцевий вимикач стосуються одного контрольованого привода. |
| Персонал | Художник або аніматор/викладач та учні (користувачі), технічний спеціаліст, розробник. | Враховуються ролі, дії користувачів і авторство команд. Положення тіла та фізіологічні показники людей не вимірюються. Їхня взаємодія з платформою відображається також у UE. |
| Матеріали | Окремі відповідники відсутні. | Манекен не обробляє сировину й не витрачає матеріали в межах змодельованого процесу. Матеріали його конструкції належать до характеристик обладнання. |
| Процес | Ручне позиціонування, дистанційна зміна кутів, відтворення збереженої пози, аварійне зупинення та відновлення роботи. | Відображаються режим роботи, цільові й фактичні кути, статуси команд і переходи між станами. |
| Приміщення | Майстерня або навчальна аудиторія, у якій використовується манекен. | Приміщення є контекстом експлуатації. Його геометрія, розташування обладнання й інженерні системи не входять до поточної моделі. |
| Довкілля | Окремі спостережувані параметри не визначено. | Температура повітря, вологість та освітленість не вимірюються. S-08 характеризує температуру привода, тому належить до обладнання, а не до довкілля. |
| Продукт | Окремий виробничий продукт у межах моделі відсутній. | Манекен формує позу для використання як референсу. Збережена поза є інформаційним результатом, який враховано в документації; створені художником малюнки й анімації не відстежуються платформою. |
| Документація | Реєстр сигналів, допустимі кути, пороги попереджень, описи збережених поз, журнал команд і подій, вимоги та архітектурні рішення. | Документи й записи описують конфігурацію, правила роботи та історію об’єкта. Збережена поза містить назву й набір шести цільових кутів. |

## Відповідність сутностей ISO 23247 складникам платформи

| Сутність ISO 23247 | Складник платформи та його відповідальність | Блок майбутньої SysML-моделі | Статус |
|---|---|---|---|
| DCE: збирання даних | Модуль контролера або емулятора, який формує відліки S-01…S-11 з ID і часовими мітками та передає їх через MQTT. Забезпечує періодичне й подієве надходження даних. Підстава: FR-01. | `DataCollection` | закрито |
| DCE: керування пристроями | Локальний модуль виконання команд: перевіряє цільові кути, керує приводами, враховує кінцевий вимикач та аварійне блокування, повертає результати виконання. Підстава: FR-03, FR-07. | `DeviceControl` | закрито |
| DTE: застосунки та служби | Сервіси роботи з позами, історією телеметрії та виявленням аномалій. Забезпечують збереження й вибір поз, діагностичні запити та формування попереджень. Підстава: FR-04, FR-06. | `TwinApplications` | закрито |
| DTE: доступ до ресурсів та обмін | Модуль доступу до сховищ і API платформи; адаптер обміну через MQTT-брокер. Надає іншим компонентам доступ до телеметрії, поз, команд і журналів. Підстава: FR-01, FR-03, FR-04, FR-08. | `ResourceAccess` | закрито |
| DTE: функціонування та керування | Менеджер стану двійника: підтримує фактичні й цільові значення, режими роботи, статуси команд, стан підключення та процедуру повторної синхронізації. Підстава: FR-02, FR-03, NFR-05. | `TwinManagement` | закрито |
| UE: користувацька сутність | Користувацький застосунок для художника, викладача, технічного спеціаліста й адміністратора: 3D-модель, панель телеметрії, керування, бібліотека поз і перегляд журналів. Підстава: FR-03…FR-06, FR-08. | `UserApplication` | закрито |
| Наскрізна сутність: захищеність | Спільний механізм автентифікації та перевірки прав на API й доступу до MQTT-тем. Обмежує надсилання команд і зміну налаштувань; забезпечує встановлення джерела дії в журналі. Підстава: NFR-06, FR-08. | `Security` | закрито |
| Наскрізна сутність: забезпечення якості даних | Перевірка структури, ID, типів, діапазонів, часових міток та актуальності даних. Запобігає заміні нового стану старими відліками; для перевірки повноти й повторних доставок використовує ідентифікацію відліків. Підстава: FR-01, FR-02, NFR-03, NFR-05. | `DataQuality` | закрито |
| Наскрізна сутність: взаємодійність | Узгоджені формати телеметрії, команд і відповідей, правила ідентифікації манекенів та сигналів, одиниці вимірювання й часові мітки. Адаптери MQTT та API забезпечують обмін між контролером, сервісами й інтерфейсом за спільними контрактами. Підстава: реєстр сигналів, FR-01…FR-03. | `Interoperability` | закрито |

Служби захищеності, якості даних та взаємодійності застосовуються до всього маршруту обміну. Наприклад, перевірка прав лише в інтерфейсі недостатня: вона має виконуватися також на вході до захищених функцій платформи.

Локальне блокування небезпечного руху належить до `DeviceControl`. Воно доповнює захищеність платформи, але має інше призначення: контролює допустимість фізичної дії незалежно від доступності мережі.

## Покриття еталонної моделі

Для платформи застосовні всі дев’ять сутностей:

- дві підсутності DCE;
- три підсутності DTE;
- користувацька сутність UE;
- три служби наскрізної сутності.

Для кожної визначено відповідний компонент і блок майбутньої моделі:

`nвідп = 9; nетал = 9`

`C = 9 / 9 × 100 % = 100 %`

Отримані 100 % характеризують повноту архітектурного відображення за переліком лабораторної роботи.

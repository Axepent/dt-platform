# ADR 0005. Синхронізація спільної 3D-сцени

Статус — прийнято для прототипу ЛР 3.

## Контекст

Інженер і експерт оглядають роботизований манекен у браузері. Їм потрібні поточні пози аватарів і спільні позначки. Дані про фізичну позу манекена вже надходять із Eclipse Ditto через SSE. Часті оновлення поз аватарів та рідші зміни позначок мають різні вимоги до актуальності й порядку доставки.

## Варіанти

1. Один сервер WebSocket для поз, присутності та позначок. Клієнти зберігають останні знімки для інтерполяції.
2. Два канали. Невпорядкований WebRTC DataChannel передає часті пози, а серверний WebSocket забезпечує порядок змін позначок.
3. Періодичні HTTP-запити за повним станом із серверними змінами через окремі HTTP-запити.

## Рішення

Обрано один сервер WebSocket для спільного стану. Учасник визначає позу свого аватара. Сервер перевіряє координати, зберігає останню коректну позу й формує знімки з частотою 20 Гц. Кожний клієнт отримує пози інших учасників. Сервер веде список позначок, присвоює ідентифікатори та дозволяє видалення підключенню, яке створило позначку.

Основний режим відображення — інтерполяція. Для LAN, City та Mobile використовуються буфери 51, 105 та 130 мс. Екстраполяція з межею 250 мс доступна як експериментальний режим для порівняння. Кожен браузер отримує телеметрію манекена через наявний канал Ditto SSE.

## Наслідки

- Впорядкована доставка спрощує синхронізацію позначок. Повторне передавання TCP може затримати нові пози, тому клієнт згладжує їх за допомогою буфера.
- У Mobile інтерполяція дала медіану 208 мс і максимальне відхилення 0,17 см. Екстраполяція скоротила медіану до 74 мс із максимальним відхиленням 12,12 см. Результати підтримують інтерполяцію як основний режим спільного огляду.
- Сервер розсилає пози кожному учаснику окремо, тому вихідний потік зростає пропорційно `N(N−1)`. Для більших сеансів потрібно оцінити відбір учасників за видимістю, зниження частоти оновлень або окремий канал поз.
- Перезапуск сервера завершує сеанс і скидає позначки з оперативної пам’яті. Фізичне керування потребує окремого авторизованого контуру з перевіркою актуальності команд і підтвердженням їх виконання.
